================================================================================
KEY CONFIGURATION CHOICES
================================================================================

BATCH SIZE: 48
  Rationale:
    - v5e TPU: 8 chips × 16GB = 128GB total
    - 500M model in BF16: ~1GB
    - Activations: ~20-30GB per chip
    - Conservative choice for 24/7 stable training
    - Can try 64 or 32 if needed

LEARNING RATE: 5e-4
  Rationale:
    - Industry standard for 500M models (LLaMA, Chinchilla, etc.)
    - Cosine decay to 1e-5 over training
    - Warmup: 2000 steps

BETA2: 0.98
  Rationale (Research):
    - LLaMA: beta2=0.95 (7B-65B)
    - Chinchilla: beta2=0.95 (70B)
    - This project: beta2=0.98 (500M)
    - Smaller models benefit from slightly higher beta2
    - Larger batch sizes (48) stabilize training
    - No need for aggressive momentum

GRADIENT CLIPPING: 1.0
  - Global norm clip prevents exploding gradients
  - Standard for transformer training

ROPE THETA: 10000.0
  - RoPE (Rotary Position Embeddings)
  - Better than absolute embeddings
  - Extrapolation friendly for future seq_len extension

SAVE INTERVAL: 1000 steps
  - Effective batch: 48 × 512 = 24,576 tokens/step
  - 1k steps = ~24.6M tokens saved
  - All checkpoints go to Google Drive automatically

================================================================================
CHECKPOINTING STRATEGY
================================================================================

SAVE BEHAVIOR:
  - Every 1000 steps to: /content/gdrive/MyDrive/checkpoints/500m_v5e/step_XXXX/
  - Each checkpoint contains:
    * params.npz (model weights)
    * optimizer_m.npz (first moments)
    * optimizer_v.npz (second moments)
    * state.json (step count, metadata)
    * model_config.json (model configuration)
    * training_config.json (training configuration)

PRUNING STRATEGY:
  - Log-spaced thinning: keeps ~log(N) checkpoints instead of N
  - Example: After 1M steps, keeps ~20 checkpoints instead of 1000
  - Saves disk space while maintaining recovery points

RESUME:
  - --auto-resume flag finds latest checkpoint automatically
  - Loads all model weights and optimizer state
  - Resumes from exact training step
  - No manual path needed

TROUBLESHOOTING
================================================================================

  → Runtime → Change runtime type → TPU v5e

Out of memory (OOM):
  → Edit configs/v5e.yaml, reduce batch_size to 32 or 24

Checkpoint save fails:
  → Create directory: !mkdir -p /content/gdrive/MyDrive/checkpoints/500m_v5e

Training slow:
  → Reduce log_interval, check HuggingFace connectivity
